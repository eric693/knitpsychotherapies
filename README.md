## 這套系統跟一般客戶管理系統的差別

心理諮商的核心限制是**保密**。系統把「行政資料」與「晤談內容」分成兩層：

| 資料層 | 誰看得到 |
|---|---|
| 個案基本資料、預約、收費、同意書 | 行政櫃檯、心理師、督導、管理者 |
| 晤談紀錄（SOAP）、處遇計畫 | **僅主責心理師本人、督導、管理者** |
| 危機事件與通報 | 心理師、督導、管理者（行政預設無權限） |

- 保密邊界由 `src/auth.js` 的 `canViewNote` / `canViewClientNotes` / `requireNoteAccess` 統一把關，
  所有讀取晤談內容的 API 都必須經過它，不是靠前端隱藏按鈕。
- 每次調閱晤談紀錄都寫入稽核軌跡（誰、何時、看了哪位個案），管理者可於「稽核軌跡」頁查詢。
- 個案端**完全不提供**任何晤談紀錄內容，只做預約、改期、取消、量表、費用、同意書與行政訊息；
  逾免收費期限的取消只會送出「取消申請」並通知櫃檯，是否計費由櫃檯決定，個案端不能自行改變收費結果。

## 功能

**每日作業**
- 總覽：今日晤談、待補紀錄、高風險個案、量表警示、處遇計畫到期、待處理來電、明日待提醒、執照與契約到期
- 我的工作台（心理師個人視角）：我的個案與高風險數、本週排程（含視訊連結）、本月／今年服務量、
  待補紀錄與待完成衡鑑報告、個案未讀訊息與待填量表、追蹤中危機事件、本月開立費用，
  以及督導時數、繼續教育積分（總積分／特定三類／專業倫理分開檢核）與執照更新倒數
- 預約排程：週檢視（含團體場次與請假）；同一心理師或同一諮商室時段衝突即時擋下；可預約時段（weekday × 時段）設定
- 行事曆：月檢視一次看完晤談、團體場次與請假，可依心理師篩選；點任一天看當日明細並直接排約
- 我的排班：心理師自己在星期 × 時段格子上點選／拖曳刷出每週可預約時段，一次存檔（管理者可代設定），
  同頁登錄請假；排班存好後櫃檯下訂與個案端預約只會看到這些時段。
  **表格起訖時間、每格分鐘數與快填按鈕皆為系統設定**（各所作息不同）；
  不在格線上的時間（如 13:15-14:05）用「自訂時段」另行加入，可一次套用到多個星期
- 行事曆訂閱（.ics）：每位心理師一組 token 網址，可加入 Google／iPhone 日曆訂閱未來半年班表；
  **只帶個案編號不帶姓名**，網址可隨時重設讓舊訂閱失效
- 候補遞補：取消或未到釋出時段時，立即依「指定心理師 → 緊急度 → 希望時段吻合 → 等候天數」
  配對候補名單並可一鍵發送遞補通知（未設發送通道時只產生文字）；「候補遞補」頁列出所有仍空著的釋出時段
- 線上視訊晤談：形式選「視訊」即帶入該心理師的固定會議室連結（帳號設定），也可逐筆指定；
  連結只收 http(s)，自動附在晤談提醒訊息中，個案於專區與心理師於今日看板皆可一鍵進入
- 今日看板：報到／完成／未到／取消一鍵處理；完成時自動扣方案次數或產生收費單，未到依比例計費
- 晤談提醒：產生明日晤談的提醒文字供複製；填入 webhook 後可由系統直接發送簡訊／LINE（單筆或整批），
  每則發送皆留紀錄含失敗原因。未設定通道時只產生文字供人工發送，不把個資送到外部服務
- 待補晤談紀錄：已完成但未寫紀錄者，逾所內規定天數以紅字標示

**總覽**
- 儀表板長條圖：近 6 個月完成晤談（滑鼠移上顯示當月未到次數）、近 6 個月實收金額、近 6 個月新收個案、
  本月各心理師完成晤談；另有「可遞補時段」與「個案端取消申請」待辦區塊

**個案服務**
- 來電登記與派案：來電 →（候補）→ 派案 → 初談建檔的完整漏斗，高風險來電標紅、等候天數超過 14 天示警
- 個案端自填初談問卷：產生免登入連結（有效天數可設定）以簡訊／LINE 傳給來電者，
  填寫基本資料、主訴、就醫史與 BSRS-5；建檔時聯絡資料與主訴一併帶入、量表轉為療效追蹤基線，
  命中自殺意念題自動標為高風險並拉高來電緊急度。尚未登記來電也可先發問卷，填完一鍵轉為來電登記
- 團體諮商：團體、成員名單、場次排程、出席點名、團體歷程紀錄（僅帶領者可讀）、出席自動計費
- 個案管理：編號自動產生（C+年份+流水）、身分證統一編號（含檢查碼驗證）、主責心理師、風險等級、
  依生日自動判定未成年（民法 18 歲，門檻可設定）、法定代理人欄位、結案摘要（可列印）
- 個案附件：轉介單、診斷證明、同意書掃描、衡鑑報告上傳（PDF／圖片／Office，單檔 20MB）；
  隨機檔名落地、目錄不對外開放、下載逐次驗權並記入稽核；可逐檔開放個案端下載
- 晤談紀錄：SOAP 格式 + 使用技術、家庭作業、風險標記；簽核定稿後比照病歷不可修改
- 實習心理師督導覆核：帳號可標記為實習生並指定督導；實習生的紀錄按「送督導覆核」後
  **不會直接定稿**，送出期間不可修改，由指定督導（或督導／管理者）覆核通過才鎖定，
  或填意見退回補正（修改後需重送）。「紀錄覆核」頁列出待覆核與被退回的紀錄，逾期未覆核紅字標示
- 安全計畫（Safety Plan）：警訊、自我因應、可轉移注意力的人事地、可求助親友、專業協助、
  危機資源、環境安全、值得活下去的理由共 8 段；**可列印一份給個案帶走**（含簽名欄）；
  內容更新以新版本保存、舊版可查；保密層級同晤談紀錄。
  「安全計畫列管」頁盯高風險個案是否都有現行計畫、是否逾預定檢視日，總覽與我的工作台皆有警示
- 處遇計畫：治療取向、個案概念化、多筆目標與進度條、預定檢視日提醒
- 心理衡鑑報告書：轉介問題、施測工具、背景資料、行為觀察、分數摘要表、綜合印象與建議；
  保密層級同晤談紀錄，簽核定稿後不可修改，可列印（抬頭帶所別資訊、落款帶證照字號）；
  已完成的心理衡鑑晤談若尚未產出報告，會列入「待補紀錄與報告」頁列管
- 心理量表：PHQ-9、GAD-7、BSRS-5（心情溫度計）、PSS-10、ISI，內建計分與切分點判讀；
  同一量表多次施測畫成折線圖（含判讀切分點與危險題標示），個案頁、處遇計畫頁與個案端皆可看；
  PHQ-9 第 9 題／BSRS-5 附加題命中即自動拉高風險等級並列入總覽警示
- 危機事件：類型、嚴重度、已採取處置、法定通報管道與案號、後續追蹤與結案；
  責任通報類型自動帶出 24 小時通報期限（類型與時限可設定），逾時未通報紅字警示並可篩選；
  **責任通報表套印**：把當事人、法代、事件概要、已採處置、通報人與單位資訊帶成一張可列印的表，
  供抄錄或附件用（實際通報仍走 113／關懷 e 起來等主管機關管道，完成後回填時間與案號）
- 轉介與結案後追蹤：轉出／轉入紀錄（對象、原因、對方是否接案與回覆時間），
  結案時依設定自動建立追蹤點（預設 30、90 天），「結案追蹤」頁列出到期與逾期者，
  完成追蹤須填結果；保密層級同晤談紀錄
- 同意書：知情同意、未成年法代同意、個資告知、錄音錄影、緊急聯絡共 5 份範本；
  手寫簽名、簽署當下全文快照；範本改版自動遞增版本，已簽者需重簽

**專業與營運**
- 督導紀錄：個督／團督／同儕，年度時數統計對照目標時數
- 請假與繼續教育：請假期間自動從可預約時段移除並擋下櫃檯下訂；繼續教育積分依執照更新週期彙總
  （特定三類合計下限與專業倫理個別下限分開檢核）與執照到期倒數
- 報酬與扣繳：心理師鐘點給付單，依設定費率試算代扣所得稅與二代健保補充保費（可人工覆寫）；
  可依當月已完成晤談批次帶入；年度依所得人與所得類別彙總，供填報扣繳憑單
- 合作單位與請款：學校認輔、企業 EAP、社政委託案的契約額度追蹤，按月彙整產生對帳單／請款單（對帳單以個案編號列示，不記載姓名）
- 收費與方案：預付堂數方案（售出即產生收費單）、單次收費、收據號、付款人別（自費／EAP／學校／社會局）
- 逾期催繳：未收款超過設定天數者列管，含帳齡分析（30／60／90 天級距）、依付款人別與主責心理師篩選、
  催繳訊息範本、單筆或整批發送（未設定發送通道時只產生文字供人工發送），每則留發送紀錄
- 電子發票與補助核銷：發票號碼與日期、買受人統編（8 碼檢核）、抬頭、載具、捐贈碼；
  政府補助方案可記方案序號、補助額與自付差額（自動拆算）。已收款者仍可補登發票欄位，金額鎖住
- 個案訊息：行政聯繫用聊天串（改期、繳費），與晤談內容分離
- 退費：已收款項需退還時另立退費單與原收費單勾稽（不動原單金額），全額退還才把原單標為已退費；
  方案退費可依剩餘堂數試算並同步停止扣次，收費頁與報表以「收款 − 退費」計算實收，誤開可撤銷
- 公告、統計報表（服務量、來源、收入、合作單位、團體、危機事件、量表施測）
- 經營品質指標：爽約率、取消率、初談轉銜率、脫落率（逾 60 天未再晤談且無後續預約）、
  平均晤談次數，以及**心理師時段利用率**（實際完成時數 ÷ 排班開放時數）；分母為 0 時顯示「—」不顯示 0%
- 報表匯出：個案清單、晤談明細、收費明細、心理師服務量、危機事件，每份皆可出
  **Excel（.xls）／PDF（列印版）／CSV（含 BOM）**；匯出記入稽核軌跡
- 收據列印、對帳單列印

**系統**
- 帳號權限：19 個模組逐一勾選；角色預設值（行政不含晤談紀錄與危機事件）；不可停用最後一位管理者；
  停用心理師時提示尚有幾筆未來預約與主責個案待改派
- 系統設定：所別資訊（含開業執照字號、負責心理師、機構統編）、收費預設、責任通報時限、
  扣繳費率、提醒發送通道、選項清單、前台文字、諮商室、同意書範本、
  排班表格線與快填、安全計畫檢視週期與危機資源、實習生覆核期限、個案端預約／改期開關
- 舊資料匯入：個案名冊、晤談排程、收費明細、量表施測四種 Excel／CSV 匯入；
  下載範本 → 上傳預覽（完全不寫入）→ 確認匯入，逐列驗證且有任一列錯誤即整批拒絕；
  可選擇略過或更新既有資料，檔案只在記憶體處理不落地，匯入結果記入稽核
- 紀錄保存與歸檔：結案滿保存年限（預設 7 年）的個案清單，系統只提示不自動刪除
- 稽核軌跡、每日自動備份（保留 14 份 + `/root/backups/mindcare` 異地鏡像，**個案附件一併同步**）；
  備份後 WAL checkpoint 回收空間，並清理無對應紀錄的孤兒附件檔

展示帳號的密碼僅供開發與測試環境使用；正式站請務必更換 admin 密碼。
登入頁的「展示用測試帳號」提示框預設為空（`ui_demo_staff`／`ui_demo_portal`），
需要展示時才到「系統設定 → 前台文字」填入，離開展示記得清空——
那個框會直接把帳號密碼印在公開的登入頁上。

## 常用指令

```bash
npm start              # 直接啟動（預設埠 3440）
npm run seed           # 建立展示資料（已有個案時不重複灌入）
npm run smoke          # API 冒煙測試（拋棄式資料庫，不碰正式資料）
npm run smoke:ui       # 前端冒煙：無頭瀏覽器巡過所有頁面抓 JS 錯誤（需執行中的伺服器）
npm run deploy         # 上線流程：API 冒煙 → 備份 → pm2 重啟 → 前端冒煙（任一步失敗即中止）
pm2 restart knitpsychotherapies   # 正式環境重啟（單獨重啟時建議改用 npm run deploy）
```

## 方案別、額度與收支（本所版新增）

### 方案 × 主題 × 心理師

收費不是一個數字，而是一組規則，因此獨立成「方案」（`service_plans`）：

| 方案設定的東西 | 用途 |
|---|---|
| 金額／可選金額 | 固定價，或像伴侶諮商那樣**由預約時挑金額**（3000／3600／4500） |
| 方案給付、核銷名稱 | 補助方案由公部門支付的部分，與個案自付差額分開記帳 |
| 晤談時長 | 40／50／80 分鐘各方案不同，排約時自動算結束時間 |
| 年齡上下限、每人每年次數 | 補助方案的資格控管（如 15-45 歲、一年 3 次） |
| 每位心理師每週／每月人次 | 名額分配（如一位心理師一週 6 人次） |
| 心理師報酬 | 抽成比例或固定鐘點費 |

方案底下再分**主題**（`plan_topics`，如伴侶溝通、親職教養），主題可覆寫金額；
再往下是**心理師費率**（`plan_counselors`），可針對某位心理師（甚至某位心理師的某個主題）
另訂金額、報酬方式與人次上限。取價順序：心理師費率 → 主題 → 方案預設（`src/plans.js` `resolveFee`）。
全部在「系統 → 方案設定」頁自行增修，不必改程式。

方案、治療主題與心理師名單依本所官網服務項目建立，由
`scripts/seed-knit.js` 維護（可重複執行，以名稱比對更新，不會產生重複資料）。
**金額為暫定值**，請於「系統 → 方案設定」改成本所實際收費：

- **自費方案**：成人個別心理治療／諮商 50 分鐘 2000、兒童青少年個別心理治療 50 分鐘 2000、
  兒童青少年團體治療 90 分鐘 1200、伴侶諮商 80 分鐘 3000、親職諮詢 50 分鐘 2000、
  通訊（視訊）諮商 50 分鐘 2000（預設線上）、EMDR 眼動減敏重整療法 80 分鐘 3000、
  初次評估會談 50 分鐘 2500
- **補助方案**：目前未建立。日後承接政府方案時於後台新增 `kind = subsidy` 的方案即可，
  個案只付場地費、其餘由方案給付的算法系統已內建。
- **治療主題**（11 項，各方案共用）：自我探索、情緒困擾、壓力調適、親密關係、原生家庭/親子關係、
  人際關係、生涯議題、心理疾患、創傷與失落、兒童青少年適應、其他（可自填）
- **心理師**：鍾芯瑜、羅捷、闕靖惠、張文藍、莊育涵（臨床心理師）、
  張益綸、許峰益、蕭如軒（諮商心理師）；初始密碼一律 `knit2026`，首次登入請自行修改

### 金額的三個角色（重要）

一次晤談的錢分成三塊，分開記才不會讓個案看到不該看的數字：

| 欄位 | 意思 | 補助方案的例子 |
|---|---|---|
| 總額 | 這次服務帳面上值多少 | 1800 |
| 方案給付 `subsidy_amount` | 由補助方案／委辦單位支付 | 1600 |
| 個案要付 `fee` | **民眾實際掏出來的錢** | 200（場地費） |

- 後台排約視窗的「個案應付金額」與線上表單顯示的都是**個案要付的錢**，
  補助方案就是 200，不會讓民眾誤以為要付 1800；下方提示才寫出總額與方案給付的拆解
- 收費單與收據開的也是 200，方案給付另存欄位供核銷
- **心理師抽成基數 = 總額 − 場地費**（`venue_fee`）。場地費全額是所方收入，不參與拆帳：
  1800 的補助方案，抽成以 1600 計，六成即 960，所方得 840（含場地費 200）
- 場地費在「方案設定」逐案可調；自費方案不設場地費，抽成基數即總額

補助方案總額目前一律以 1800 元（給付 1600 + 場地費 200）建立，
各方案實際給付若不同，於「方案設定」改總額與方案給付即可。

帳號旗標：`portal_bookable` 控制是否出現在公開表單的心理師清單（示範與行政帳號已關閉），
`online_only` 標示僅接受線上通訊諮商者（表單會標注，成立預約時一律以視訊安排）。

### 額度控管

- **個案年度次數**：已用次數 = 系統內該年度有效預約 + 人工調整（他所已使用過的次數）。
  個案頁與預約表單都看得到「用了幾次」，用滿即擋下，只剩 1 次時提前警示。
- **心理師人次上限**：以週一起算的自然週計。額滿時錯誤訊息直接附上
  「下週（起日）尚餘 N 人次」，櫃檯與個案都能當場改約下週。
- 兩種上限預設**擋下**（`plan_quota_enforce`，可改為僅警示）；
  櫃檯確認仍要排時可強制排入，該決定會寫進稽核軌跡。
- 「方案人次」頁一次看完每位心理師在各限量方案的本週／本月用量，並可直接：
  **調整上限**（沿用方案／不限／個別上限；心理師只能改自己的，改別人需 settings 權限）、
  **填已用人次**（把他所已接、系統外排的場次填成實際數字，存的是與系統統計的差額，
  之後系統內新增預約仍照常累加）、**刪除整個方案**（已被使用過的改為停用）。

### 每位心理師每月收支

「心理師收支」頁（`GET /api/plan-income`）依方案別結算：完成場次、應收總額、
方案給付與自付拆分、心理師報酬、所方淨收，以及實收／未收。
心理師報酬在晤談完成當下鎖定（`appointments.counselor_share`），
事後調整方案費率不會回頭改動已結算的月份。單一心理師的當月明細可列印對帳。

## 安裝成 App（PWA）

員工端與個案端都可安裝到手機或電腦主畫面，不必上架商店：

- 員工端 `/manifest.json`（名稱「織心後台」，含今日看板／預約排程／線上預約申請三個捷徑）
- 個案端 `/portal.manifest.json`（名稱「織心」，深色圖示以便與後台區分）

- **刻意不做離線**：`public/sw.js` 對 HTML、`/api`、`/uploads` 一律不快取，

- 部署新版後 App 內會提示「已有新版本」，按下即套用；`sw.js` 與 manifest 由
  `src/server.js` 送 `Cache-Control: no-cache`，避免改版被瀏覽器快取擋住
- 圖示在 `public/icons/`，由 `scripts/` 外的 Pillow 腳本產生（心形，員工端青綠、個案端深綠）

## 收據

收據與收費單分開：收費單是帳，收據是給個案的憑證。個案談完當下要就開一張，
不要的話事後也能補開（「收據」頁的「待開立」清單直接列出已收款但沒開收據的收費單）。

- 流水編號：前綴 + 年月 + 四碼序號（如 `KN2026080001`），作廢的號碼不回收；
  收費單（收款時配號）與收據（開立時配號）共用同一條序列，兩份單據不會出現同一個號，
  資料庫另有唯一索引把關，撞號時系統會重算一個號再寫入
- 補印會累計次數與時間，事後查得到這張印過幾次
- 開錯不塗改：作廢並「重開」新號，新舊互相勾稽（`reissue_of`）
- 個案端在「費用」頁看得到自己的收據編號，需要紙本時報編號給櫃檯補印
- 已綁定 LINE 的個案可直接把收據以 Flex 卡片傳過去

## 線上預約表單與空間配置

`/booking.html` 是公開免登入的手機版表單，欄位順序比照所內原本的 Google 表單：
**諮商方案 → 諮商主題 → 預約之心理師 → 時段 → 基本資料**，三個選項欄位都是下拉式選單。

- **個案全程看不到諮商室配置**：表單與個案專區都不出現空間資訊，
  諮商室由系統在成立預約時自動挑一間當下沒被占用的（`src/plans.js` `pickRoom`）
- 時段已排除被占用、請假與帶團體的時間，並依方案人次上限過濾；
  某週額滿時直接顯示「本週已排滿，下週起尚可預約」
- 補助方案的年齡與年度次數在表單端就先擋，個案不會白填一輪才被退
- 送出的是「預約申請」（`booking_requests`），櫃檯在「線上預約申請」頁確認後才寫進排程；
  未建檔者可一鍵由表單資料建檔。方案可個別設定免審
- 主題選「其他」時可自填；心理師選「由諮商所安排合適之心理師」時不列時段，
  改請個案填可配合時段，由櫃檯排定後回覆
- 表單欄位、注意事項與個資告知文字皆在系統設定可改

## LINE 官方帳號（Flex Message）

**串接在「系統 → LINE 官方帳號 → 串接設定」頁完成**，不必碰程式或設定檔：

1. **頻道憑證**：貼上 LINE Developers Console 的 Channel access token（long-lived）與 Channel secret
   （已存的權杖只顯示末四碼，不改就留原樣），按「驗證連線」會向 LINE 取回官方帳號名稱與 ID 確認打得通
2. **Webhook**：按「寫回 LINE 並測試」，系統直接把
   `https://knitpsychotherapies.crownai.ink/api/line/webhook` 設定到 LINE 頻道並請 LINE 實際回打一次；
   同時記得到 LINE 後台關閉「自動回覆訊息」與「歡迎訊息」，改由本系統回覆
3. **通知時間與樣式**：晤談提醒提前時數、心理師行程每日推播時間、Flex 卡片主色、
   放在卡片按鈕上的預約表單網址

同頁另有「綁定管理」（員工與個案的綁定狀態，逐一發綁定碼或解除）
與「推播與紀錄」（手動推播、每筆推播結果與失敗原因）。
未完成串接時系統完全不對外連線，訊息只記錄為「待人工發送」，不會把個資送到未設定的服務。

| 卡片 | 對象 | 時機 |
|---|---|---|
| 已收到預約申請 | 個案 | 從 LINE 進表單送出申請後 |
| 預約已成立 | 個案 | 櫃檯確認申請、或櫃檯直接排約（個案已綁定 LINE 才推） |
| 晤談提醒 | 個案 | 晤談前（預設 24 小時；系統每 10 分鐘檢查一次，與心理師行程推播各自獨立，時數填 0 即不推），可單筆或整批推 |
| 預約申請未能成立 | 個案 | 櫃檯回覆無法安排時 |
| 新的預約申請／新排入的晤談 | 心理師 | 有人指名預約、被排入新個案、或個案自己在專區排約 |
| 明日晤談行程 | 心理師 | 每日設定時間自動推播（預設 20:00） |
| 收據已開立 | 個案 | 櫃檯按下「LINE 傳給個案」 |

綁定不必手抄 userId：後台產生 6 碼綁定碼 → 對方在官方帳號輸入 → Webhook 完成綁定。
Webhook 簽章以 channel secret 驗證，驗不過即忽略。

## Google 表單同步

所內的「織心心理治療所 預約表單」
（<https://docs.google.com/forms/d/1P5quvQySzH2f8xraVyWSAXk8CvPTTojHo_5-lJQmckI/edit>）不必停用——
在「系統 → Google 表單同步」頁產生密鑰、把頁面上的 Apps Script 程式碼貼到表單的
指令碼編輯器並設定「表單提交時」觸發器，之後每一筆回應都會即時寫入後台的
「線上預約申請」，櫃檯不必再謄一次。

- 方案／主題／心理師以**選項文字自動對應**（會自動忽略「(２０００／５０分鐘)」這類價目說明）；
  對不到時仍收單，並在申請上標示「需人工指定」，資料不會掉
- **這份表單的每一題都會存下來**：姓名（成人段「就診者姓名」／兒青段「孩子姓名」）、
  電話（「您的電話」／「家長的電話」）、email、生理性別、出生年月日、預約類別、教育程度、
  「想尋求協助的主要原因」→ 主訴、「期待得到的幫忙」→ 期待、「預約時間」→ 其他可配合時段；
  另外整份回應原樣存進 `booking_requests.form_answers`，申請頁最下方可展開看到每一題的原文，
  日後表單加題目也不會漏接
- 按「由申請資料建檔」時，上述資料連同教育程度、家長電話、期待（寫進備註）一併帶進個案基本資料，
  未滿 18 歲自動標記為未成年
- 方案名稱與表單「預約項目」的選項同名（`scripts/seed-knit.js` 維護），
  改表單選項時記得一併改後台方案名稱，否則會變成「需人工指定」
- 「是否指定心理師」選「不指定，由所方媒合…」時不指定心理師，不會誤判成未對應
- 表單常用全形數字（`(２０００／５０分鐘)`），比對前會先轉半形再剝掉價目說明
- 電話會正規化（去掉空白與破折號、`+886` 轉 `0`），舊個案以電話自動比對
- 同一筆回應重送不會產生第二筆（以 Google 的 response id 去重）

### 歷史回應要走試算表，不是 backfill()

Apps Script 的 `backfill()` 只拿得到「該筆回應當時、且現在仍存在」的題目。
這份表單改過版，舊回應缺姓名與 email 等欄位，補送時會全部被擋在「缺少姓名或聯絡電話」。
歷史資料改走回應試算表（它保留了每一個欄位，含後來刪掉的題目）：

```bash
# 表單 →「回應」分頁 → 試算表圖示 → 檔案 → 下載 → 逗號分隔值 (.csv)
node scripts/import-form-responses.js 回應.csv          # 試算，先看對不對
node scripts/import-form-responses.js 回應.csv --apply  # 實際寫入
```

以「時間戳記」去重，重跑不會產生第二筆；對應規則與即時同步共用
`src/form-ingest.js`，兩條路進來的資料長得一樣。
- 端點為 `POST /api/integrations/google-form`，以共用密鑰驗證（固定長度比較），
  密鑰可隨時重新產生

本系統自建的表單（`/booking.html`）欄位已與 Google 表單一致，兩邊可並行；
差別是自建表單能即時擋掉資格不符與額滿的時段、能直接選時段，且會回推 LINE 通知。

## LINE 的預約流程

1. 個案加入官方帳號（@032cjyby）→ 系統自動回一張卡片，上面有「開始預約」按鈕
2. 個案隨時輸入任意訊息（例如「預約」）也會再收到同一張卡片
3. 按鈕帶的是**一次性連結**（`/booking.html?bk=<token>`，效期 3 天）：
   網址只帶隨機 token，不帶 LINE userId；表單送出時後端才以 token 換回身分，
   因此預約成立、晤談提醒、收據都推得回同一個人，而 userId 不會出現在網址列或瀏覽紀錄
4. 已是本所個案者，收到櫃檯發的 6 碼綁定碼後在聊天室輸入即完成綁定（見上一節）

## 上線前健檢

```bash
node scripts/preflight.js               # 設定、方案金額、排班、帳目一致性、備份一次檢查
node scripts/migrate-fee-semantics.js   # 舊制「fee＝總額」的預約轉為「fee＝個案自付」（--apply 才寫入）
node scripts/purge-demo.js              # 清除 seed 的示範帳號與示範個案（--apply 才刪，會先自動備份）
npm run smoke                           # API 冒煙測試（拋棄式資料庫，不碰正式資料）
npm run smoke:ui                        # 無頭瀏覽器巡過所有頁面，抓 JS 例外與空白頁
bash scripts/deploy.sh                  # 驗 → 備份 → 重啟 → 再驗
```

`preflight.js` 會把「阻擋上線的問題」與「提醒」分開列，前者不清乾淨不建議上線。

## 目前關閉的功能

- **實習心理師督導覆核**：所內暫無實習生，`intern_review_enabled` 設為 `0`，
  「紀錄覆核」頁與帳號設定裡的實習生欄位都不出現。日後收實習生時改成 `1` 即回復。
- **暫不使用的模組**：系統設定 `hidden_modules` 目前為
  `groups,hr,supervision,partners,overdue,risk,safety`——
  團體諮商、請假與繼續教育、督導紀錄、合作單位請款、逾期催繳、危機事件與通報、安全計畫列管
  都不出現在導覽列、總覽看板與個案分頁。功能與資料都還在，把代碼從設定移除即回復。
